# Chat side questions (btw) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ask a Side question about a Claude Agent's conversation from the Composer's btw mode, answered by a separate `claude -p` process on a fork of the Transcript, streamed into a card above the Composer, without touching the Agent or its Transcript.

**Architecture:** Rust `transcript/btw.rs` builds the `claude -p --resume … [--fork-session]` argv, runs it through a new line-streaming Transport helper, parses stream-json into `BtwEvent`s sent over a Tauri `Channel`, and deletes the fork on close. The frontend keeps one thread per Pane in a zustand store (`src/chat/btw.ts`), a btw mode in `Composer`, and a `BtwCard` in `ChatLens`.

**Tech Stack:** Rust (tokio, serde_json, uuid, tauri `ipc::Channel`), React + zustand, vitest, cargo test.

**Spec:** `docs/superpowers/specs/2026-10-10-chat-btw-design.md`

## Global Constraints

- Claude only; pi and other agents are out. The btw button shows only when `canFork(agent, located) && located.agent === "claude"`.
- Never write to the original Transcript. The only file a Side question deletes is `<dir of Transcript>/<fork id>.jsonl` where the fork id parses as a UUID and differs from the Transcript's own stem.
- No `--tools`, `--allowedTools`, `--permission-mode` or `--max-turns` flags: the prefix must match the Agent's for the cache.
- Rust errors use `AppError::new(code, message)` with the existing codes: `invalid`, `not_found`, `io`. Messages are lowercase English, e.g. `"claude not found on this machine"`.
- Event wire format (serde `tag = "kind"`, snake_case): `{"kind":"delta","text"}`, `{"kind":"tool","name"}`, `{"kind":"done","fork_id","cache_read","input"}`, `{"kind":"error","message"}`. TS mirrors it as `BtwEvent` in `src/lib/types.ts`.
- Card and mode copy (exact): button `btw` (title `Side question (Cmd+B)`), placeholder `Hỏi bên lề (không vào Transcript)…`, buttons `Dừng`, `Hỏi tiếp`, `Đóng`, tool line `⚙ <name>`.
- The btw Draft key is `btw:` + `paneKey(pane)`, through the existing `readDraft`/`writeDraft`/`useDraft`.
- Run Rust tests with `cd src-tauri && cargo test <filter>`; frontend with `pnpm test <file>` and `pnpm typecheck`. After `cargo fmt`, revert formatting changes to files this plan does not touch.
- Docker, if ever needed, runs on `devtuf` over ssh, never locally.

## Review Focus

- A question that starts with `-` (e.g. `--help?`) must reach Claude as the prompt, not as a flag: argv puts it after `--` (Task 2 test).
- A Transcript whose last lines carry no `cwd` or `model` (fresh or compacted): no `cwd` is `not_found`, no model just omits `--model` (Task 2 tests).
- Closing a card while its turn still runs must cancel the process before discarding, so a late `Done` cannot recreate the thread (Task 5 test).
- The Pane switching to another Transcript discards the old thread's fork (Task 7 test).
- `discard` is handed the Transcript's own id or a path-like id (`../x`): refused, nothing removed (Task 4 test).

  - `pub fn parse_line(line: &str) -> Vec<BtwEvent>`

argv shape: `["sh", "-c", CLAUDE_SCRIPT, "sh", cwd, program, "-p", "--resume", <id>, ("--fork-session" only when fork_id is None), ("--model", m when Some), "--output-format", "stream-json", "--include-partial-messages", "--verbose", "--", question]`, where `<id>` is `fork_id` or else `transcript_id`.

`CLAUDE_SCRIPT` (exact):
```sh
cd "$1" || exit 1; shift
p="$1"; shift
c=$(command -v "$p") || c=$("${SHELL:-/bin/sh}" -lc "command -v $p" 2>/dev/null | tail -n 1)
[ -n "$c" ] || { echo "claude not found on this machine" >&2; exit 127; }
exec "$c" "$@"
```

`parse_line` rules: `stream_event` whose `event.type == "content_block_delta"` and `event.delta.type == "text_delta"` → `Delta`; `assistant` line → one `Tool` per `tool_use` block (its text is ignored, the deltas already carried it); `result` with `is_error == false` → `Done` from `session_id`, `usage.cache_read_input_tokens` (0 if absent), `usage.input_tokens` (0 if absent); `result` with `is_error == true` → `Error` with `result` text (else `subtype`); anything else, including non-JSON → `[]`.

**Interfaces:**

- Produces:
  - `pub async fn ask(t: &dyn Transport, remote: bool, program: &str, path: &str, question: &str, fork_id: Option<&str>, cancel: tokio::sync::oneshot::Receiver<()>, emit: &mut (dyn FnMut(BtwEvent) + Send)) -> AppResult<()>`
    1. `path` must be absolute (`invalid`), else read it with `exec_bytes(["cat", path])` (`io` on failure, as `fork.rs` does).
    2. `cwd = last_cwd` (None → `not_found`, `"the transcript has no working directory"`); `model = last_model`; transcript id = file stem.
    3. `spawn_lines(t, &btw_argv(program, …), remote)`; loop `tokio::select!` over `cancel` (→ drop the child, return `Ok(())` without emitting) and `next_line` (each `parse_line` event goes to `emit`; non-JSON lines go into a ring of the last 5).
    4. At EOF: `finish()`. If no `Done`/`Error` was emitted, emit `Error { message }` built from the stderr tail, else the ring, else `format!("claude exited with {status}")`.
  - `pub async fn discard(t: &dyn Transport, path: &str, fork_id: &str) -> AppResult<()>` — `invalid` unless `uuid::Uuid::parse_str(fork_id)` is ok and `fork_id` ≠ the Transcript's stem; then `exec(["rm", "-f", "--", "<dir>/<fork_id>.jsonl"])`, `io` on a non-zero exit.
  - `#[derive(Default)] pub struct BtwRuns(std::sync::Mutex<HashMap<String, oneshot::Sender<()>>>)`, managed with `app.manage(BtwRuns::default())` in `lib.rs`.
  - Commands in `commands.rs`, registered in `lib.rs` after `chat_fork`:
    - `chat_btw_ask(mgr: Mgr, runs: State<'_, BtwRuns>, machine_id: String, path: String, question: String, fork_id: Option<String>, ask_id: String, events: Channel<BtwEvent>) -> Result<(), AppError>` — inserts the cancel sender under `ask_id`, calls `ask` with `program = "claude"` and `remote = machine_id != crate::machines::LOCAL`, sends each event with `events.send`, removes `ask_id` when done.
    - `chat_btw_cancel(runs: State<'_, BtwRuns>, ask_id: String) -> Result<(), AppError>` — sends on and removes the sender; unknown id is `Ok`.
    - `chat_btw_discard(mgr: Mgr, machine_id: String, path: String, fork_id: String) -> Result<(), AppError>` — `discard`.
