# Chat Fork Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A Fork button on each user message in the Chat lens starts a new Agent in a new Tab whose Transcript is the original cut just before that message, with the message's text waiting in its Composer.

**Architecture:** The backend cuts the Transcript by parent chain (pure functions in `transcript/fork.rs`), writes the copy next to the original through the Machine's Transport, and returns the new session's id, path and cwd (`chat_fork`). The frontend opens a Tab at that cwd, writes the Composer draft, and starts the agent with `agent.start` `args` (`--resume <id>` / `--session <path>`).

**Tech Stack:** Rust (Tauri 2, serde_json, chrono, uuid), React + TypeScript, zustand, vitest.

**Spec:** `docs/superpowers/specs/2026-10-10-chat-fork-design.md`

## Global Constraints

- Commands: Rust tests `cd src-tauri && cargo test`; frontend `pnpm test`, `pnpm typecheck`, `pnpm lint` (scripts in `package.json` / `mise.toml`). Never run bare `cargo fmt` over the crate: format only the files you edited (`rustfmt --edition 2021 <file>`).
- Errors are `AppError::new(code, message)` with the existing codes: `not_found` (entry id missing), `invalid` (bad input, unsupported agent, non-UTF-8 file), `io` (read/write on the Machine failed). Messages start lowercase, like the rest of the crate.
- Supported agents for forking are exactly `"claude"` and `"pi"` (the `agent` string herdr reports); anything else is `invalid` in Rust and hides the button in TS.
- Agent args: Claude `["--resume", id]`, pi `["--session", path]`, none when the fork has no id.
- The frontend toast text on any failure is `Could not fork: ${message}` where `message` is `(err as { message?: string } | null)?.message ?? String(err)` (the pattern in `src/App.tsx`).
- Commit messages: Conventional Commits in the repo's voice, e.g. `feat(chat): …`, `test(chat): …`.

## Review Focus

- A Claude Transcript with an abandoned branch (after a rewind) between the root and the forked message: the copy must hold only the chain, never the abandoned lines. Pinned in Task 2.
- Forking a message whose parent id is missing from the file (a truncated or hand-edited Transcript): the walk stops there and the copy holds what was found, not an error. Pinned in Task 2.
- A Transcript path on a remote Machine containing spaces or quotes: the write goes through argv (`"$1"`), never string-built shell. Pinned in Task 3 (path with a space).
- Forking twice from the same message: two distinct sessions, never an overwrite (`set -C` + fresh UUID). Pinned in Task 3.
- The new Pane must not flash the Terminal lens when the user set new agents to open on Terminal: a fork always ends on Chat. Pinned in Task 4.

### Task 2: Cutting a Transcript by parent chain

**Files:**
- Create: `src-tauri/src/transcript/fork.rs`
- Modify: `src-tauri/src/transcript/mod.rs` (`pub mod fork;`)

**Interfaces:**
- Produces:
  ```rust
  pub struct Cut { pub id: String, pub file_name: String, pub text: String, pub cwd: Option<String> }
  pub fn cut_claude(text: &str, entry_id: &str, new_id: &str) -> AppResult<Option<Cut>>;
  pub fn cut_pi(text: &str, entry_id: &str, new_id: &str, now: chrono::DateTime<chrono::Utc>) -> AppResult<Option<Cut>>;
  ```

Rules (from the spec):
- Parse each non-empty line as JSON; lines that do not parse or have no id (`uuid` for Claude, `id` for pi) are not in any chain.
- Find the line whose id is `entry_id` (`not_found` error, message `entry {entry_id} not found in transcript`, if none). Walk from its parent (`parentUuid` / `parentId`) to the root through the id map; stop at a null parent or at a parent id not in the file. If an id appears twice, the later line wins.
- Keep the chain's lines in file order. pi additionally keeps its first `"type":"session"` line, always first.
- `Ok(None)` when the chain holds no conversation: no Claude line with `type` `user` or `assistant`, no pi line with `type` `message`.
- Claude: every kept line gets `sessionId = new_id` (re-serialized); `file_name = "{new_id}.jsonl"`; `cwd` = `cwd` of the last kept line that has one.
- pi: header `id = new_id`, `timestamp = now` as `%Y-%m-%dT%H:%M:%S%.3fZ`; other kept lines byte-identical; `file_name = "{now as %Y-%m-%dT%H-%M-%S-%3fZ}_{new_id}.jsonl"`; `cwd` = header's `cwd`.
- `text` is the kept lines joined with `\n`, ending with `\n`.
